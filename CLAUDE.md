# Сайт — инструкции для Claude

Статический сайт на Vite + чистые HTML/CSS/JS. Язык интерфейса и общения — русский.

## Команды

- `npm run dev` — dev-сервер на http://localhost:5173
- `npm run build` — сборка в `dist/`
- `npm run check` — линт + сборка + тесты. Запускай перед каждым коммитом.
- `npm run test` — Playwright-тесты (desktop + mobile)
- `npm run screenshot -- /about.html` — скриншоты страницы в `.screenshots/` (нужен запущенный dev-сервер)
- `npm run format` — Prettier по всему проекту

## Структура

- `*.html` в корне — страницы. Каждый новый HTML-файл автоматически становится страницей (см. `vite.config.js`).
- `src/styles/tokens.css` — цвета, шрифты, отступы. Новые значения добавляй сюда, а не хардкодь в других файлах.
- `src/styles/base.css`, `layout.css` — сброс и общая раскладка; стили отдельных страниц — в `src/styles/pages/`.
- `src/scripts/` — JS-модули, точка входа `main.js`.
- `public/` — файлы, которые копируются как есть (favicon, изображения, robots.txt).
- `tests/` — Playwright-тесты. `docs/plans/` — планы задач.

## Дизайн

Сайт — портфолио «675 agency» (графический дизайн и брендинг). Концепция, токены и запреты — в `docs/plans/2026-10-15-design-675-agency.md`, сверяйся с ним при любых визуальных правках. Для нового интерфейса используй скилл `frontend-design`.

- Закладки справа (`src/styles/tabs.css`, `src/scripts/tabs.js`) — единственный смелый элемент. Новый раздел = новая закладка + `id` и `data-section` у секции.
- Работы лежат в `public/works/` (WebP, вертикальный формат A), каждая — `<article class="work">` в `index.html`.

## Правила кода

- Семантичная разметка: `header`/`main`/`nav`/`footer`, один `h1` на странице, `alt` у изображений, у каждой страницы свои `title` и `meta description`.
- Mobile-first, без горизонтального скролла на ширине 360px. Бренд строго чёрно-белый, тёмной темы нет: цвет дают только работы.
- Без фреймворков и новых зависимостей, если пользователь не попросил.
- ES-модули, без глобальных переменных. Prettier форматирует файлы автоматически после правок (хук).

## Как работаем

1. Небольшая правка — сразу делай. Задача крупнее — сначала скилл `/plan`: исследуй, запиши план в `docs/plans/`, дождись подтверждения.
2. Реализуй по плану маленькими шагами.
3. Проверка: `/verify` (линт, сборка, тесты) и `/screenshot` для изменённых страниц. Если пользователь дал макет — итерируй по скриншотам до совпадения.
4. Коммить только когда проверки прошли, сообщение — по-русски в повелительном наклонении («Добавь форму обратной связи»).
